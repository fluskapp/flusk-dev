flusk

An autonomous coding agent that owns its whole loop.

Not a wrapper around another agent CLI. flusk runs its own turn/tool/session engine, keeps every run on an isolated flusk/<runId> branch with per-turn checkpoints, and writes what it learns about your repositories to a local bitemporal fact store — so knowledge outlives the context window.

Download Source · Apache-2.0

Safe unattended

Four layers, in order: conservative shell-command classification (unknown commands are denied), a realpath filesystem write jail, git-branch isolation with hooks disabled, and hard budgets for turns, dollars and wall-clock. The classifier is deliberately boring TypeScript — its value is that it has been read.

Everything on disk

Sessions are append-only, fsynced JSONL. Crash mid-run, lose at most one entry, resume where you were. Facts are bitemporal: a status change closes the old row instead of mutating it, so history stays readable and a concurrent reader never sees two live answers.

A real workbench

An IntelliJ-styled desktop app: numbered tool windows for runs, docs, search, chat, documentation, flows, the code graph and the web — every token in its theme traced to the IDE theme dumps it was measured from. The address bar names the whole workbench state.

Quoted material stays quoted

Everything flusk quotes into a prompt — your repo's docs, its own history — sits inside <<<FLUSK-CONTEXT ...>>> fences, and the sentinel is neutralised inside quoted bodies, so a document in a cloned repository cannot close the quotation it was placed in and continue as instructions. A cloned repo's config cannot name the binaries the workbench spawns, or the directories the history indexer reads. The details are in SECURITY.md — including how to tell us when you get past them.

Fast where it counts

The CPU-bound floor — history indexing and search today, scanning, rendering and the fact store as they prove out — moves to Rust behind a stable TypeScript interface, with differential tests holding both implementations byte-equal and FLUSK_NATIVE=0 as a runtime kill switch. Budgets are checked in CI: sub-100ms index rebuilds, sub-10ms search, a main process that never blocks.
